    Tokens and mail merge¶

    Use this page to look up how CiviCRM tokens insert database values into emails and printed materials, and to find token examples and link formats.

    How tokens work¶

    Tokens represent fields in your CiviCRM database. You can use them to mail merge emails and printed materials, such as letters and mailing labels. For example, a Postal Greeting token can add a customised greeting to each recipient’s PDF letter. Most contact fields, including custom fields created for your site, are available as mail merge tokens.

    Contact data tokens¶

    To address each email recipient by first name, type Dear in the HTML Format field, then use Insert Tokens at the top right to find and select “First name”. After you click Close, the message reads Dear {firstname}. CiviCRM inserts the appropriate first name when each email is sent.

    Browse the Insert Tokens pop-up for the available contact data tokens, including custom fields created for your site.

    Organisation tokens¶

    You can insert standard organisation information. For example, “Domain (organizational) address” displays the address defined at Administer > Communications > Organization Address and Contact Info.

    Tokens in emails¶

    Emails can use additional tokens, including action tokens for links that let recipients opt out or unsubscribe. Some tokens, such as one that links to a message stored online, are available only for mass mailings.

    Note: In the HTML format editing area, put tokens that generate URLs in the URL field of the Link creation screen. Otherwise, the recipient’s email client displays the URL as text rather than a clickable link.

    Action tokens¶

    Action tokens can insert links for actions such as opting out and unsubscribing. To display these links properly in HTML messages, add the appropriate link tags using the editor’s Source icon.

    Required tokens for CiviMail mailings¶

    Every CiviMail mailing must include either the opt-out token, {action.optOutUrl} or the unsubscribe token, {action.unsubscribeUrl}, and the organisational address token, {domain.address}. Put them in the mailing body, header or footer. If your organisation uses a standard mailing footer, including the tokens there means people do not have to add them to each new mailing.

    Clickable unsubscribe and opt-out links are generally friendlier for recipients than the reply-to email method. You can provide both options. See the entries for the opt-out token, unsubscribe token and organisational address token below.

    Checksum links¶

    A checksum lets you send someone a link to a contribution form, profile, petition or event registration form pre-filled with information already in their contact record. This can save them from entering the same information again. You can also ask people to review and update their contact information.

    Warning: Checksum links last for seven days from the time the email is sent. You can change this duration at Administer > System Settings > Misc (Undelete, PDFs, Limits, Logging, etc.), but use caution: anyone with a link that remains valid can access that user’s account. In some cases, this could give them full account access for a long period.

    In a CiviMail message, a link containing {contact.checksum} lets CiviCRM identify the recipient and pre-fill available information on the contribution form or profile. The token {contact.checksum} supplies the full cs=checksum value, so do not add cs= to the URL yourself. {contact.checksum_value} supplies only the checksum.

    For tokens used with Form Builder, see the secret links section in creating new forms.

    Site tokens¶

    Starting in CiviCRM 5.76, Site Tokens let site administrators define pre-set snippets for content that uses CiviCRM’s standard token-handling features. Site Tokens marked “reserved” are also inserted automatically in specific places, such as Message Templates.

    For example, {site.message_header} is inserted automatically at the top of every Message Template. Its default value is empty. An administrator can give it content such as an organisation logo or other branding without editing each Message Template directly. Administrators can also create any number of additional Site Tokens.

    Site Tokens appear in the Insert Tokens utility under “Site”. For example, a Site Token labelled “Lorem Ipsum” becomes available when creating an email:

    Users with the “edit system workflow message templates” permission can manage Site Tokens at Administer > Communications > Site Tokens. See Available tokens for the Site Token listed in this page.

    Custom tokens¶

    Developers can create custom tokens—for example, to display a contact’s total contributions. See the Developer Guide on custom tokens.

    Date tokens¶

    Dates and times can use full words, abbreviations, numbers and different regional formats, such as MM/DD/YYYY and DD/MM/YYYY. An administrator may configure date preferences during system setup. Tokens such as {event.start_date}, {domain.now} and {contact.created_date} are formatted automatically according to those preferences.

    From CiviCRM v5.43+, the |crmDate filter lets you format an individual date token. The examples below use {domain.now}.

    Configured formats¶

    CiviCRM includes approximately seven configurable formats. On new deployments, the initial configuration follows English (US) conventions; organisations often adjust it for their language and locale.

    Format name Example token Example value (US English)
    “Complete Date and Time” (default) {domain.now|crmDate:"Datetime"} September 18th, 2022 11:58 PM
    “Complete Date” (default) {domain.now|crmDate:"Full"} September 19th, 2022
    “Short Date” {domain.now|crmDate:"shortdate"} 09/18/2022
    “Month and Year” {domain.now|crmDate:"Partial"} September, 2022
    “Time Only” {domain.now|crmDate:"Time"} 1:34 PM
    “Year Only” {domain.now|crmDate:"Year"} 2022
    “Financial Batch” {domain.now|crmDate:"FinancialBatch"} 09/19/2022

    Ad hoc formats¶

    Ad hoc formatting codes can specify details such as the month, day, year, day of the week, day of the year, week of the year and time zone.

    Example token Example value
    {domain.now|crmDate:"%B %Y"} September 2022
    {domain.now|crmDate:"%m/%Y"} 09/2022
    {domain.now|crmDate:"%l:%M %P"} 1:34 PM

    For the full list of formatting codes, see the PHP Manual: strftime().

    Smarty in mail templates¶

    Mail templates use Smarty to include variables, tokens and functions. See the Smarty manual for a tutorial, including if/then logic.

    Warning — system administrator required: For Smarty to work, a system administrator must add or modify the following line in civicrm.settings.php. The file is under sites/default/ for Drupal and administrator/components/com_civicrm for Joomla.

    phpdefine('CIVICRM_MAIL_SMARTY', 1);

    You can use CiviCRM tokens within Smarty. To check whether a field has a value before using it, use the |boolean modifier:

    {if {contact.email_primary.email|boolean}}
  Email: {contact.email_primary.email|boolean}
{/if}

    Token modifiers¶

    Add a modifier after a pipe in a CiviCRM token. For example, {contribution.total_amount} is a token to which a modifier could be added.

    Modifier Effect
    upper Uppercase
    lower Lowercase
    capitalize Title case, with each word capitalised
    boolean Returns 0 or 1
    crmDate Formats a date; see Date Tokens
    default Returns the value if it exists and is not falsy in PHP; otherwise returns the value you provide. For example, {contact.first_name|default:"friend"} returns friend when the contact has no first name.

    CiviMail click tracking for tokenised links¶

    Up to CiviCRM version 5.34, CiviMail did not track clicks on links containing tokens. From version 5.35, the FlexMailer extension shipped with CiviCRM can track links with tokens in URL query parameters.

    For example, a personalised Contribution Page link can pre-fill fields for its recipient:

    <a href="https://example.org/civicrm/contribute/transact?reset=1&amp;id=1&amp;cid={contact.contact_id}&amp;{contact.checksum}">Donate now</a>

    Here, cid uses {contact.contact_id}, and {contact.checksum} generates code such as cs=aaaaaaaaaaaaa.... The mailing report counts clicks on Donate now and lists the tracked link without the tokens: https://example.org/civicrm/contribute/transact?reset=1&amp;id=1.

    The following rules describe tracking and the safety of links containing tokens:

    • Token location: Tokens in the query part of a URL can be tracked. Tokens in the domain, path or entire URL cannot.
    • Tracked: https://example.org/somepage?magic={some.token}
    • Not tracked—token in domain: https://{some.token}.org/
    • Not tracked—token in path: https://example.org/{some.token}
    • Not tracked—token is the whole URL: {some.token}
    • Mixed query parameters: Query parameters with and without tokens can appear in any of these orders:
    • https://example.org/somepage?magic={some.token}&amp;x=1&amp;y=two
    • https://example.org/somepage?x=1&amp;y=two&amp;magic={some.token}
    • https://example.org/somepage?x=1&amp;magic={some.token}&amp;y=two
    • Fragments: Tokens can appear in a URL fragment, but the fragment is not included in the tracked part of the URL:
    • https://example.org/spa#{some.token}
    • https://example.org/spa?cid={contact.id}#{some.token}
    • URL safety: A token’s expanded value must be URL-safe. This does not determine whether a link is tracked, but an unsafe value can break a link or pose a security risk.
    • URL-safe: https://example.org/somepage?cid={contact.id} — a Contact ID is a number.
    • Not reliably URL-safe: https://example.org/somepage?cid={contact.first_name} — a first name could contain other characters.
    • Depends on the custom token: https://example.org/somepage?mycustom={mycustom.token} — its code would need to output URL-safe data, such as a numeric ID, a hex hash or a rawurlencoded value.
    • CMS safety: The expanded value must also be safe for the CMS:
    • https://drupal.example.org/?q={some.token} — Drupal uses q for its own purposes. This could be valid in special cases where the token is a valid Drupal path.
    • https://wordpress.example.org/?action={some.token} — WordPress has many reserved terms that are not allowed.

    Available tokens¶

    The entries below give each token’s listed purpose, where it can be used and an example. Where the source does not confirm every possible location, that uncertainty is retained.

    {action.optOutUrl}¶

    • Purpose: Provides an opt-out link for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: You can also <a href="{action.optOutUrl}" >opt-out of all future mailings from us</a>.

    {action.optOut}¶

    • Purpose: Provides an opt-out email address for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: To opt-out of all mailings from us, send mail to {action.optOut}.

    {action.reply}¶

    • Purpose: Provides a reply-to email address for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: To reply to this mailing, send mail to {action.reply}.

    {action.resubscribeUrl}¶

    • Purpose: Provides a re-subscribe link for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: You may <a href="{action.resubscribeUrl}" >resubscribe to this mailing</a> at any time.

    {action.resubscribe}¶

    • Purpose: Provides a re-subscribe email address for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: To resubscribe to this mailing, send mail to {action.resubscribe}.

    {action.subscribe.gid}¶

    • Purpose: Provides an email address to subscribe to a specific group.
    • Used in: Mailing Body, Header, Footer.
    • Example: To subscribe to our Monthly Newsletter, send mail to {action.subscribe}.

    {action.subscribeUrl.gid}¶

    • Purpose: Provides a link to subscribe to a specific group; gid is that group’s CiviCRM ID.
    • Used in: Mailing Body, Header, Footer.
    • Example: You can <a href="{action.subscribeUrl.2}" >subscribe to our Monthly Newsletter</a>.

    {action.subscribeUrl}¶

    • Purpose: Provides a link to view and subscribe to any public mailing lists.
    • Used in: Mailing Body, Header, Footer.
    • Example: If you’re interested, <a href="{action.subscribeUrl}" >view all our mailing lists and sign up!</a>.

    {action.unsubscribeUrl}¶

    • Purpose: Provides an unsubscribe link for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: You can <a href="{action.unsubscribeUrl}" >unsubscribe from this mailing</a> at any time.

    {action.unsubscribe}¶

    • Purpose: Provides an unsubscribe email address for each recipient.
    • Used in: Mailing Body, Header, Footer, Unsubscribe, Resubscribe.
    • Example: To unsubscribe from this mailing, send mail to {action.unsubscribe}.

    {contact.custom_nn}¶

    • Purpose: Displays the content of custom contact field nn.
    • Used in: Mailing Body and Subject; use elsewhere is uncertain.
    • Example: Thanks for indicating your interest in {contact.custom_1}. We will keep you updated on that topic.

    {contribution.custom_nn}¶

    • Purpose: Displays the content of custom field nn for the contribution.
    • Used in: Mailing Body and Subject; use elsewhere is uncertain.
    • Example: Thanks for indicating that if your first choice for where we should use your contribution is {contribution.custom_42}.|

    {domain.address}¶

    • Purpose: Displays the postal address for your domain.
    • Used in: Mailing Body or any message templates.
    • Example: Mailing Address: {domain.address}

    {domain.email}¶

    • Purpose: Displays your domain’s email address.
    • Used in: Mailing Body or any message templates.
    • Example: Or send a mail to {domain.email}.

    {domain.name}¶

    • Purpose: Displays your domain name.
    • Used in: Mailing Body or any message templates.
    • Example: This mailing is from {domain.name}.

    {domain.phone}¶

    • Purpose: Displays your domain’s phone number.
    • Used in: Mailing Body or any message templates.
    • Example: To contact us call {domain.phone}.

    {mailing.group}¶

    • Purpose: Lists the names of the groups to which a mailing has been sent.
    • Used in: Mailing Body, Header, Footer, Resubscribe, Unsubscribe or Optout.
    • Example: This mailing has been sent to the members of {mailing.group}.

    {mailing.name}¶

    • Purpose: Displays the mailing name.
    • Used in: Mailing Body, Header, Footer, Resubscribe, Unsubscribe or Optout.
    • Example: Name of this mailing is {mailing.name}.

    {mailing.viewUrl}¶

    • Purpose: Creates a “View in Browser” URL.
    • Used in: Mailing Body.
    • Example: Can’t see this email? <a href="{mailing.viewUrl}"><strong>View in Browser</strong></a>

    {resubscribe.group}¶

    • Purpose: Displays the group name in re-subscribe messages.
    • Used in: Resubscribe Message.
    • Example: As requested, you have been resubscribed to {resubscribe.group}.

    {site.message_header}¶

    • Listed purpose: Displays the newly joined group name in a welcome message. The source also describes this token as the automatically inserted header for Message Templates; see Site tokens.
    • Used in: Default Message Templates automatically; anywhere tokens are provided.
    • Default value: Empty.
    • Example customised value: <h4>CiviCRM<\h4><img src="https://drupal.example.org/sites/all/modules/civicrm/i/logo_lg.png">

    {subscribe.group}¶

    • Purpose: Displays the group name in subscription confirmation requests.
    • Used in: Subscription confirmation request.
    • Example: You requested to be subscribed to the {subscribe.group}.

    {unsubscribe.group}¶

    • Purpose: Displays the group name in unsubscribe confirmation messages.
    • Used in: Unsubscribe Message.
    • Example: You have been unsubscribed from {unsubscribe.group}.

    {welcome.group}¶

    • Purpose: Displays the newly joined group name in a welcome message.
    • Used in: Welcome Message.
    • Example: Welcome to {welcome.group}.
