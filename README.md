# CiviDoc Pipeline

CiviDoc combines several CiviCRM documentation repositories into one
consistent MkDocs website.

The pipeline:

- fetches the upstream documentation repositories;
- cleans and normalises Markdown pages;
- generates consistent front matter;
- assigns Diátaxis categories;
- infers topics, components, audiences and levels;
- records source commits and Git modification dates;
- detects relevant CiviCRM versions;
- creates category and audience browse pages;
- builds deterministic or AI-assisted navigation;
- optionally installs a LibreTranslate language switcher;
- builds and publishes the documentation with MkDocs Material.

## Project structure

```text
cividoc-pipeline/
├── cividoc.py
├── cividoc_content.py
├── cividoc_metadata.py
├── cividoc_nav.py
├── cividoc_translation.py
├── civicrm_versions.csv
├── requirements.txt
├── README.md
└── .cividoc/
    ├── upstream/
    ├── docs/
    ├── state/
    ├── site/
    └── mkdocs.yml
```

### Python modules

| Module | Responsibility |
|---|---|
| `cividoc.py` | Command-line interface and pipeline orchestration |
| `cividoc_content.py` | Prompts, labels, taxonomies and generated styles |
| `cividoc_metadata.py` | Front matter, Git dates, versions and inference |
| `cividoc_nav.py` | Page inventory, navigation and browse indexes |
| `cividoc_translation.py` | LibreTranslate integration and protected terminology |
| `.cividoc/` | Generated sources, state, documentation and site output |

The `.cividoc/` directory is generated by the pipeline. It is not a
Python source module.

## Requirements

- Python 3.11 or newer;
- Git;
- a Python virtual environment;
- optionally, access to a supported AI provider;
- optionally, a LibreTranslate instance.

## Prepare the documentation

Fetch or update the repositories, clean the Markdown files and regenerate
the front matter:

```powershell
python .\cividoc.py prepare
```

Generated metadata may include:

```yaml
***
title: Create an event booking form
category: tutorial
topic: events
subtopic: event-registration
component: FormBuilder
audiences:
  - event-manager
  - administrator
level: intermediate
journey_stage: daily-work
summary: Learn to create an event booking form with online payment.
source_repository: civicrm/civicrm-user-guide
source_path: events/booking-form.md
source_commit: abcdef123456
last_modified: 2026-10-08
civicrm_version:
  - "6.18"
  - "6.19"
***
```

## Diátaxis categories

Every page belongs to one primary documentation category:

| Category | Purpose |
|---|---|
| `tutorial` | Provide a guided learning experience |
| `how-to` | Help a competent reader complete a task |
| `reference` | Describe fields, options and system behaviour |
| `explanation` | Explain concepts, context and design decisions |

The primary navigation remains functional. Diátaxis categories are exposed
through separate browse indexes.

## Audiences

A page can target more than one audience:

- newcomers;
- operations users;
- fundraising managers;
- membership managers;
- event managers;
- communications managers;
- CiviCRM administrators;
- technical teams.

Explicit page metadata can prevent automatic audience enrichment:

```yaml
audiences:
  - administrator
  - technical
audiences_locked: true
```

## Generate navigation

Create a deterministic navigation plan:

```powershell
python .\cividoc.py plan --refresh-nav
```

Request a new AI-assisted navigation plan:

```powershell
python .\cividoc.py plan `
  --ai-nav `
  --refresh-nav
```

The validator requires every page ID to appear exactly once. Invalid AI
plans are rejected automatically. After three unsuccessful attempts, the
pipeline uses the deterministic fallback.

To remove only the cached navigation manifest:

```powershell
Remove-Item `
  ".\.cividoc\state\navigation-manifest.json" `
  -ErrorAction SilentlyContinue
```

## Browse indexes

The pipeline generates styled browse pages for:

- Diátaxis categories;
- audiences;
- topics;
- documentation levels.

Each page card can display:

- the page title;
- topic and component;
- difficulty level;
- summary;
- relevant CiviCRM versions;
- last modification date.

The shared stylesheet is generated at:

```text
docs/css/cividoc-index-pages.css
```

It is registered in `mkdocs.yml` through:

```yaml
extra_css:
  - css/cividoc-index-pages.css
```

## Build the website

Run a strict build:

```powershell
python .\cividoc.py build
```

Warnings stop strict builds. This helps prevent broken links and invalid
navigation from being published.

For temporary previewing despite warnings:

```powershell
python .\cividoc.py build --no-strict
```

## Preview locally

Start the local MkDocs server:

```powershell
python .\cividoc.py serve
```

The website is normally available at:

```text
http://127.0.0.1:8000/
```

Run the complete pipeline and start the server:

```powershell
python .\cividoc.py run `
  --ai-nav `
  --no-strict `
  --serve-after
```

Force a new AI navigation plan as part of the run:

```powershell
python .\cividoc.py run `
  --ai-nav `
  --refresh-nav `
  --no-strict `
  --serve-after
```

## MkDocs warnings

Save strict-build output to a log file:

```powershell
python .\cividoc.py build *>&1 |
  Tee-Object .\mkdocs-strict.log
```

Display warnings and errors:

```powershell
Select-String `
  -Path .\mkdocs-strict.log `
  -Pattern "WARNING|ERROR"
```

Use `--no-strict` for previewing only. A production release should ideally
pass the strict build.

## Translation

The optional translation module installs a browser language switcher backed
by LibreTranslate.

Generated assets include:

```text
docs/js/libretranslate-language-switcher.js
docs/css/libretranslate-language-switcher.css
```

The translation layer protects:

- code blocks;
- commands;
- URLs;
- identifiers;
- CiviCRM component names;
- protected CiviCRM terminology.

### Local LibreTranslate

Run LibreTranslate with Docker:

```powershell
docker run `
  --rm `
  -p 5000:5000 `
  libretranslate/libretranslate
```

Test the service:

```powershell
Invoke-RestMethod `
  -Uri "http://127.0.0.1:5000/languages"
```

A local documentation preview can use:

```text
http://127.0.0.1:5000
```

A public GitHub Pages website cannot use the visitor's local LibreTranslate
instance. Public translation requires an HTTPS endpoint configured to allow
the GitHub Pages origin through CORS.

## Publish to GitHub Pages

Commit the source files first:

```powershell
git add `
  cividoc.py `
  cividoc_content.py `
  cividoc_metadata.py `
  cividoc_nav.py `
  cividoc_translation.py `
  civicrm_versions.csv `
  requirements.txt `
  README.md

git commit -m "Update the modular CiviDoc pipeline"
git push origin main
```

Locate the generated MkDocs configuration:

```powershell
$mkdocsConfig = Get-ChildItem `
  -Path .\.cividoc `
  -Filter mkdocs.yml `
  -Recurse |
  Select-Object -First 1
```

Check the selected path:

```powershell
$mkdocsConfig.FullName
```

Publish the current website:

```powershell
python -m mkdocs gh-deploy `
  -f $mkdocsConfig.FullName `
  --force
```

## Versioned publication

Mike can publish several documentation versions to the same GitHub Pages
branch.

The generated MkDocs configuration includes:

```yaml
extra:
  version:
    provider: mike
```

Publish a version:

```powershell
python -m mike deploy `
  --push `
  --update-aliases `
  -F $mkdocsConfig.FullName `
  2026.10.14 `
  latest
```

Set the default version:

```powershell
python -m mike set-default `
  --push `
  -F $mkdocsConfig.FullName `
  latest
```

List published versions:

```powershell
python -m mike list `
  -F $mkdocsConfig.FullName
```

Published URLs will look like:

```text
[https://ushamakoa.github.io/cividoc-pipeline/2026.10.14/](https://ushamakoa.github.io/cividoc-pipeline/2026.10.14/)
[https://ushamakoa.github.io/cividoc-pipeline/latest/](https://ushamakoa.github.io/cividoc-pipeline/latest/)
```

## Code quality

Install the optional analysis tools:

```powershell
python -m pip install ruff vulture
```

Check imports and undefined names:

```powershell
ruff check `
  .\cividoc.py `
  .\cividoc_content.py `
  .\cividoc_metadata.py `
  .\cividoc_nav.py `
  .\cividoc_translation.py `
  --select F401,F811,F821,F841
```

Find potentially unused functions:

```powershell
vulture `
  .\cividoc.py `
  .\cividoc_content.py `
  .\cividoc_metadata.py `
  .\cividoc_nav.py `
  .\cividoc_translation.py `
  --min-confidence 80
```

Review Vulture results before removing code because some functions may be
used indirectly.
